# Contributing

This repository backed a live two-hour workshop for 75–150 people, and is published so
others can run or adapt it. The bar for a change is not "it builds" — it is "it still
teaches the right thing in the room."

## Setup

```bash
npm install
python3 -m pip install -r analysis/requirements.txt
node_modules/.bin/playwright install chromium   # for e2e, figures, control audit
npm run dev
```

Node >= 22.12 (Vite 7's floor). Python 3.12+ with numpy and scipy.

## The five rules that matter

1. **No runtime statistics.** The browser selects among precomputed summaries; it never
   fits a model. Everything numeric is generated offline by `analysis/`.
2. **Static-first.** The scenario platform must work fully as static assets behind a CDN.
   The polling backend is a separable track: with it unreachable, polling degrades to
   unavailable and every module still works.
3. **No individual-level genetic data.** Aggregate and synthetic only.
4. **Every displayed number must be derivable.** If a value cannot be traced to
   `analysis/`, it does not belong in a bundle. The `provenance` block is rendered in the
   app, so this is enforced by the validator, not just by convention.
5. **Controls must visibly do something.** Shipping an inert slider is worse than shipping
   no slider — in a workshop about analytic choices having consequences, a control with no
   consequence teaches the opposite lesson. `npm run audit:controls` checks it; the manual
   walkthrough below is the real test.

## Gotchas

- Workspace binaries (`vitest`, `tsc`, `playwright`, `vite`, `eslint`) hoist to the
  **root** `node_modules/.bin`. Prefer the npm scripts.
- Run `npm run test:e2e` and `audit:controls` from the repository root. Elsewhere Playwright
  does not find `apps/web/playwright.config.ts`, and every test fails instantly with no
  `baseURL` — which looks like an assertion failure and is not one.
- `apps/web/public/data/` is gitignored and generated by `scripts/sync-data.mjs`. Edit
  bundles through the generator, never in `apps/web/public/`.
- `VITE_BASE_PATH` (the GitHub Pages sub-path) is read from the shell by `vite.config.ts`,
  deliberately not through `loadEnv`: in `.env.local` it would move the dev server to the
  sub-path too, and every Playwright spec resolves against a root `baseURL`.
  `normalizeBase` in `src/basePath.ts` adds the trailing slash Vite does not.

## Changing scenario data

Numbers are computed, never typed. Edit `analysis/generate_scenarios.py`, never
`data/scenarios/*.json`.

```bash
python3 analysis/generate_scenarios.py
git diff data/scenarios    # empty unless you intended a change
```

An empty diff is what proves the committed bundles actually came from the generator.

**Check the output, not just the exit code.** Three of six scenarios once produced numbers
that inverted or erased their own teaching point while exiting zero. After a generator
change, read the numbers and confirm the module still argues what it claims to argue.

## Verification

```bash
npm run lint
npm run validate:data
npm run test
npm run build
npm run test:e2e
npm run test:polling-load
npm run audit:controls    # opens every module, confirms every control moves pixels
```

Then, **non-optional and not substitutable by tests**: `npm run dev`, open all six
modules, and move *every* control. Inert sliders passed every automated check in this
repository for months.

## Writing a regression guard

Make it fail first. A guard that passes against the buggy code is not a guard — one e2e
test here asserted on the scenario title, which the facilitator run sheet also renders as
a heading, so it passed with the bug present. Assert on something only the fixed state can
satisfy, and confirm the failure before you accept the test.
