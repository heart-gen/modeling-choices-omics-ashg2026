# Scenario Data Schema 0.2.0

Scenario bundles in `data/scenarios` are synthetic, aggregate-only JSON files. The
browser selects among precomputed values; it never fits a statistical model at runtime.

Required fields:

- `schemaVersion`: currently `0.2.0`.
- `scenarioId`, `title`, `subtitle`, `estimatedMinutes`, and `learningObjectives`.
- `controls`: no-code UI controls, defaults, and complete slider/select domains.
- `variant`: optional named-variant metadata (`rsid`, gene, locus, trait).
- `ancestryGroups` and `alleleFrequencies`: optional aggregate group metadata. Compute-only
  scenarios may omit them.
- `simulatedEffects`, `associationResults`, and `powerEstimates`: precomputed statistical
  summaries; scenario-specific optional arrays include `localAncestryResults` and
  `modelPerformance`.
- `interpretation`: prediction prompt, what changed, why it matters, and facilitator note.
- `infoPanels`: optional prose cards (`title`, `paragraphs[]`) rendered verbatim under the
  charts, for provenance a participant should see without opening the provenance panel
  (module 6's "Where the prices come from"). The validator rejects an empty one.
- `provenance`: generator version, seed, alpha, real reference inputs, synthetic inputs,
  and assumptions used to derive every displayed result.

## Visualization summaries

Each `vizSummaries` entry is either a flat array or a grid keyed by an interactive
control. Flat arrays are used when a chart does not change with control state:

```json
"alleleFrequency": [{ "label": "African ancestry", "groupId": "afr", "af": 0.11 }]
```

Control-keyed entries name the controlling field and provide an array for every allowed
control value:

```json
"reported": {
  "byControl": "heterogeneity",
  "values": {
    "0": [{ "label": "Fixed-effect summary", "modelId": "fixed_meta", "p": 1.6e-22, "detected": true }],
    "10": [{ "label": "Fixed-effect summary", "modelId": "fixed_meta", "p": 2.1e-22, "detected": true }]
  }
}
```

Keys are `String(controlValue)`. `scripts/validate-scenarios.mjs` checks every chart key
the app reads and rejects grids missing any declared slider, toggle, or select value.
Bundles must be generated by `analysis/generate_scenarios.py`, never hand-edited.

Rows that stand for an ancestry group carry `groupId`, and rows that belong to one analysis
strategy carry `modelId`. The charts colour by `groupId` (a group keeps one colour across the
platform) and give everything else a strategy colour from `apps/web/src/chartColors.ts`, so a
pooled or summary row can never borrow a group's colour. `modelId` is what the "model" select
*filters*: a chart draws the rows of the selected strategy (plus rows marked `pinned`, the
group estimates a summary combines), so switching the select changes what is plotted rather
than only an opacity. Each chart's data table carries a `shown` column saying which rows the
screen currently draws. A grid may also be keyed by the select itself (`byControl:
"modelId"`), as module 5's `coefficientPath` is, or by toggles (keys `true` / `false`), as
module 4's grids are keyed by `sampleSize|clinical|technical`.

The top-level `alleleFrequencies` array is not a chart: the control panel renders it as the
"Fixed at this locus" table, next to the controls, with each group's colour and `n` from
`ancestryGroups`.

Where parameters interact, a grid may be keyed by several controls at once. The key is
each control's value in `byControls` order, joined by `|`:

```json
"detection": {
  "byControls": ["betaAfr", "betaEur", "afrShare", "totalN"],
  "values": {
    "0.12|-0.08|50|15000": [{ "label": "Global ancestry PCs", "p": 0.92 }]
  }
}
```

The validator requires an entry for **every** combination the controls can reach, because
a missing one does not error in the app: `resolveVizSeries` falls back to the defaults, and
the control looks inert. Number keys are normalised to ten decimal places by `gridKeyPart`
(app), `gridKeyPart` (validator) and `js_key` (generator), so range-input arithmetic like
`-0.039999999999999994` still finds `-0.04`.

## Prediction and presets

Optional per module:

- `prediction`: the multiple-choice question participants commit to before the controls
  unlock — `pollId`, `question`, `options`, and `correctOptionId`. The generator computes
  the correct option from the precomputed results; it is never hand-entered. The question
  and options must match that poll in `backend/polling/poll.mjs` exactly, which the
  validator enforces: a mismatch would project one answer while counting another.
- `presets`: named starting points (`id`, `label`, `description`, `state`) that set several
  controls at once, so a wide parameter space has legible places to start.

## Columnar series

A chart whose x-axis is identical in every cell of a grid stores that axis once, and each
cell holds one row of equal-length columns instead of one object per point. The regional
signal in `global-vs-local-ancestry` is the case that needs it: 1,029 cells x 21 positions
repeated the position and the significance line 21,609 times each.

```json
"regionalPositions": [{ "positions": [11.66, 11.68] }],
"regionalThreshold": [{ "value": 3.2 }],
"regional": {
  "byControls": ["betaAfr", "betaEur", "afrShare", "totalN"],
  "values": { "0.12|-0.08|50|15000": [{ "global_pc": [0.03, 0.04], "local_covariate": [0.26, 0.27] }] }
}
```

`scripts/validate-scenarios.mjs` checks that every cell holds exactly one row and that each
column has one value per position. A length mismatch is otherwise invisible: the chart plots
a truncated curve and every other check stays green.

## File formatting

Bundles are written with two-space indentation while a person could plausibly read the diff,
and without indentation above `PRETTY_MAX_BYTES` (1 MB) in `analysis/generate_scenarios.py`.
A bundle carrying a multi-control grid runs to millions of characters either way, and there
the indentation is pure cost — on disk, in git history, and in every participant's download.
Compacting the regional grid and dropping the repeated columns took that bundle from 5.9 MB
to 1.3 MB, and its gzipped transfer from 211 KB to 127 KB.
